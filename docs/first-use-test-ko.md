# 처음 쓰는 사람 테스트

[English](first-use-test.md)

[목적별 사용법](recipes-ko.md)을 따라 해 보면 패널이 문서대로 동작하는지는 확인할 수 있어요.
하지만 패널을 처음 보는 사람이 어디서 막히는지는 알 수 없어요. 따라 하는 사람이 이미 길을
알기 때문이에요. 이 테스트는 그걸 봐요. 패널을 처음 보는 사람에게 문서 없이 과제를 주고 지켜봐요.

패널이 바뀌는 릴리즈 전, 그리고 과제를 하는 방법이 바뀔 때마다 해요. 결과는
[verification-log.md](verification-log.md)에 남겨요.

## 준비

- **참가자:** Necto는 써 봤지만 Map Local은 처음인 iOS 개발자나 QA. 한 명이면 가장 큰 문제를
  찾고, 세 명이면 대부분을 찾아요.
- **앱:** 참가자가 아는 앱. 페이지 쿼리를 받는 JSON 요청으로 그리는 목록 화면이 있어야 해요.
  시뮬레이터에서 실행하고, Map Local을 등록한 뒤 그다음에 Necto 네트워크 플러그인을 등록해
  둬요([실제 응답 캡처하기](usage-ko.md#실제-응답-캡처하기)).
- **시작 상태:** Map Local 켜짐, 허용 호스트 없음, 규칙 없음. 왼쪽에 시뮬레이터, 오른쪽에
  Map Local 패널을 연 Necto.
- **진행자:** 과제를 읽어 주고, 시간을 재고, 기록해요. 설명하거나 가리키지 않아요. 한 과제에서
  3분 넘게 막히면, 막힌 곳을 풀 만큼의 가장 작은 힌트를 주고 기록해요.
- **참가자에게는 생각을 말로 해 달라고 부탁해요:** 무엇을 찾는지, 이 컨트롤이 무엇을 할 거라고
  기대하는지, 무엇이 뜻밖이었는지.

## 과제

적힌 그대로 읽어요. 컨트롤 이름은 말하지 않아요.

1. "목록 화면이 빈 목록으로 보이게 해 주세요."
2. "같은 화면이 서버가 500으로 실패했을 때의 에러를 보여 주게 해 주세요. 그다음 원래 목록으로
   되돌려 주세요."
3. "그 목록이 불러오는 데 3초가 걸리게 해 주세요."
4. "2페이지만 다른 데이터가 나오게 하고, 1페이지는 그대로 두세요."
5. "설정한 것을 모두 꺼서, 앱이 다시 실서버와 통신하게 해 주세요."

## 과제마다 기록할 것

| 항목 | 방법 |
| --- | --- |
| 완료 | 완료, 힌트 받고 완료, 못 함 |
| 시간 | 과제를 읽은 때부터 앱에 결과가 보일 때까지 |
| 첫 동작 | 처음 누르거나 본 것 |
| 머뭇거림 | 5초 이상 멈춘 순간마다, 어디를 보고 있었는지 |
| 헛걸음 | 도움이 안 된 클릭, 그리고 그걸로 무엇을 기대했는지 |
| 쓴 말 | 참가자가 쓴 말이 패널의 말과 다를 때 그 말 |
| 힌트 | 준 힌트가 있다면 |

## 과제가 끝난 뒤

세 가지를 묻고, 말한 그대로 적어요.

1. 가장 어려웠던 과제는 무엇이고, 왜였나요?
2. 패널이 예상과 다르게 움직인 곳은 어디였나요?
3. 다음에 다시 쓴다면 무엇부터 찾을 건가요?

## 결과 읽기

- 두 명 이상이 힌트를 받은 과제는 교육 문제가 아니라 결함이에요.
- 두 명이 같은 곳에서 헛걸음했다면, 그 컨트롤의 자리나 이름이 잘못된 거예요. 참가자의 말과
  패널의 말을 비교해요.
- 같은 곳에서 머뭇거렸다면, 그 자리에 무언가가 빠진 거예요. 상태, 이유, 또는 다음 단계요.
- 고칠 때는 패널을 먼저 바꿔요. 문서에 문장을 더하는 건 마지막 수단이에요.

