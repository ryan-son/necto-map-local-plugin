# 문제 해결

[English](troubleshooting.md)

증상을 표에서 찾고 옆의 확인 사항을 따라 하세요. 패널의 각 부분이 하는 일은
[usage-ko.md](usage-ko.md)에 있어요.

## 증상 찾기

| 증상 | 확인 |
| --- | --- |
| 규칙이 맞지 않아요 | 그 호스트가 허용 호스트에 있고, 앱 코드에서 차단한 호스트(`blockedHosts`)는 아닌가요? 「트래픽」 탭에서 그 요청의 결과가 「실서버」인가요? 「허용 호스트만」이 켜져 있으면 허용되지 않은 호스트로 간 요청은 목록에 보이지 않아요. 「다른 호스트」를 누르면 흐리게 보여요. 그다음 [요청이 목업되지 않은 이유](#요청이-목업되지-않은-이유)를 보세요 |
| 패널에 「앱 연결을 기다리는 중…」이 보여요 | 앱이 Debug 빌드로 실행 중인가요? Necto에서 그 앱을 골랐나요? |
| `module<NectoMapLocalPlugin>` 컴파일 오류 | [빌드 구성 이름 규칙](release-builds-ko.md#빌드-구성-이름-규칙-따르기)을 따르세요 |
| 허용 호스트로 가는 요청이 421을 받아요 | 「규칙 없는 요청」이 「차단(421)」이에요. 필요한 규칙을 추가하거나 「실서버로 보내기」로 바꾸세요 |
| 허용 호스트로 가는 요청이 오프라인처럼 실패해요(-1009, -1005, -1001) | 「규칙 없는 요청」이 오류로 되어 있어요. 필요한 규칙을 추가하거나 「실서버로 보내기」로 바꾸세요 |
| 맞는 규칙이 있는데 목업되지 않았다고 트래픽 상세가 알려요 | 한 줄 이유를 따르세요. 이유별 해결 방법은 [요청이 목업되지 않은 이유](#요청이-목업되지-않은-이유)에 있어요 |
| Necto에 앱이 보이지 않아요 | 한 앱의 빌드 여러 개(Dev 빌드와 운영 빌드 등)가 함께 설치돼 있을 수 있어요. 플러그인을 등록하는 코드가 든 빌드를 실행하세요 |
| 새로 설치한 앱의 요청이 운영 서버로 가요 | 앱에서 서버 환경을 바꾸기 전까지는 앱의 기본값이 운영 서버일 수 있어요. `blockedHosts`는 운영 서버를 목업하지 않게 할 뿐, 그 요청은 통과시켜요 |

## 요청이 목업되지 않은 이유

「트래픽」 탭에서 그 요청을 골라요. 맞는 규칙이 있는데 목업되지 않았다면, 트래픽 상세가 그
이유를 한 줄로 알려 주고 옆에 해결 버튼을 둬요.

![규칙이 꺼져 있다고 알려 주고 옆에 「규칙 켜기」를 둔 트래픽 상세](images/recipe-why-not-mocked.png)

| 상세가 알려 주는 것 | 해결 |
| --- | --- |
| Map Local이 꺼져 있음 | 「켜기」 |
| 허용 호스트가 아님 | 「허용 호스트에 추가」 |
| 규칙이 꺼져 있음 | 「규칙 켜기」 |
| 앱 코드에서 차단한 호스트 | 패널에서는 할 수 없어요. 앱의 `blockedHosts`가 목업을 막아요 |
| 지금은 규칙이 적용됨 | 앱에서 다시 요청해요 |
| 트래픽에서 방금 만든 규칙이 응답하지 않음. 규칙 조건: `_=100` · 이 요청: `_=200` | 「_ 조건 지우기」. 지우면 그 규칙이 이 요청에 응답하게 될 때만 보여요 |

맞는 규칙이 아예 없다면 메서드·경로·쿼리를 기대한 규칙과 비교해 보세요. 규칙이 무엇과 맞아야
하는지는 [규칙 매칭](usage-ko.md#규칙-매칭)에 있어요. 행의 호스트가 흐리게 보이면 허용 호스트가
아니라는 뜻이에요. 그런 행은 「다른 호스트」를 누르거나 「허용 호스트만」을 끄면 보여요.
