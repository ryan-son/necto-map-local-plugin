# Map Local 패널 — 경험 정의

[English](experience.md)

## 의도

**앱을 만지는 손을 멈추지 않고, 지금 보고 있는 화면의 데이터를 몇 초 안에 원하는 응답으로 바꾸고, 바뀐 것을 확인해요.**

핵심 루프는 하나예요 — **보기 → 고르기 → 바꾸기 → 확인**. 모든 화면 요소는 이 루프의 한 단계를 빠르게 하거나, 루프를 끊는 불확실성(지금 켜졌나? 적용됐나? 저장됐나?)을 없애기 위해 존재해요. 이 둘 중 어디에도 해당하지 않는 요소는 빼요.

사용자는 시뮬레이터(또는 기기)와 Necto를 나란히 띄운 iOS 개발자·QA예요. 시선과 손이 두 창을 오가요. 그래서 패널은 **한눈에 읽혀야** 하고(앱에서 눈을 떼는 시간이 짧게), **키보드로 끝까지 갈 수 있어야** 해요(마우스로 작은 표적을 찾는 시간이 짧게).

## 원칙

1. **Necto와 하나처럼 (호스트 일관성)** — 사용자는 바로 옆 Necto Network 패널에서 이미 배웠어요. 같은 것은 같게 해요.
   - 실측(Necto 0.2.0 Network 패널): 열 머리글이 있는 표, 상태 코드 앞 색 점(2xx 초록·실패/5xx 빨강), ↑↓로 행 이동, 선택 행 왼쪽 강조선, 상세는 오른쪽 분할 + 탭(요약·요청·응답·cURL) + ×, 필터 칸 「메서드, 호스트 또는 경로 필터」 + 건수 + 「비우기」.
   - ⌘F는 호스트의 「패널에서 찾기」예요 — **가로채지 않아요.** 우클릭 메뉴는 호스트도 제공하지 않아요(「다시 로드」만) — 만들지 않아요.
2. **키보드로 루프를 끝까지** — 목록 ↑↓ 이동(Necto와 같게), ⇞⇟/Home/End, Return = 상세의 주 동작으로 초점, Esc = 한 단계 물러나기(입력 지우기 → 선택 해제), 목록↔상세↔필터 Tab 순서, 주 동작(「이 응답으로 목업」)에 단축키와 버튼 위 표기. 초점은 항상 보여요.
   - 실측(Necto 0.2.0 WKWebView, 2026-10-04): ↑↓·Return·⌘↩·`/`는 패널에 와요. **⌘Z(편집 메뉴 「실행 취소」)와 Esc는 호스트가 가져가 패널에 오지 않아요.** 그래서 되돌리기·닫기·지우기는 늘 보이는 버튼(되돌리기·×·ⓧ)이 주 경로이고, 키는 덤이에요. WebKit 기본값에서 Tab은 버튼을 건너뛰므로 루프의 컨트롤에는 `tabindex="0"`을 줘요.
   - 실측(2026-10-05): Necto가 활성 창이 아닐 때 첫 클릭은 창을 앞으로 가져오기만 하고 페이지에 오지 않아요. Necto 자체 Network 패널도 같아요. 시뮬레이터와 오가는 것이 핵심 루프이므로 목적별 사용법에서 한 번 알려 줘요.
3. **상태는 늘 보여요** — 켜짐/꺼짐, 일시정지, 필터로 숨긴 수, 목업 적용 여부, 저장 여부. 확인하려고 다른 곳을 열어야 하면 실패예요.
4. **되돌릴 수 있게, 묻지 않게** — 지우기는 바로 하고 「되돌리기」를 줘요(확인 대화상자 대신). 편집은 자동 저장 + 「저장됨」. 단, 실서버로 토큰이 나갈 수 있는 동작만은 물어요. 목업 세션이 남아 있을 때 인증 규칙 끄기·지우기, 그리고 켜진 인증 규칙이 응답하는 동안의 Map Local 끄기·허용 호스트 빼기예요. 태그가 보이지 않는 트래픽 상세에서 인증 규칙을 켤 때도 물어요. 규칙 목록과 편집기는 태그를 보여 주므로 바로 켜요.
5. **자리가 흔들리지 않게** — 새 데이터·배너·필터 변화가 목록을 밀거나 스크롤·선택을 잃게 하지 않아요. 보던 자리를 지켜요. 헤더는 무엇이 들어 있든 두 줄을 유지해서, 호스트를 추가해도 목록이 움직이지 않아요(실측: 전에는 25px 움직였어요).
6. **폭마다 의도가 있게** — 좁음(<640): 한 번에 한 가지(목록 또는 상세, 위아래). 보통(640–1100): 목록+상세 나란히. 넓음(>1100): 상세에 공간을 줘요(본문이 주인공). 탭(규칙/트래픽) 모두 같은 규칙.
7. **기억해요** — 보기 방식, 탭, 분할 폭, 필터는 보는 사람별로 기억(localStorage, 실패해도 동작).
8. **읽히는 말** — 내부 식별자·영문 기술어 대신 사용자의 말. 잘린 글은 hover로 전부 보여요. 색은 뜻이 하나예요(목업=보라, 실서버=회색, 차단=주황, 실패/5xx=빨강, 4xx=노랑, 2xx=초록).
9. **접근성** — role(listbox/option·tablist/tab), aria-selected/pressed가 화면과 일치, 대비, 동작 줄이기 설정 존중.
10. **앱은 실서버와 말하지 않을 때만 그렇다고 말해요** — Map Local이 켜져 있으면 Necto가 있든 없든 규칙이 적용돼요. 앱은 무언가 적용될 때만 배지를 보이고, 배지를 누르는 것이 빠져나가는 길이에요. 적용 중인 것을 말하고 Map Local을 꺼요. 적용되는 것이 없으면 앱에는 아무것도 보이지 않아요.

## 시나리오 × 원칙 (성공 조건)

| 시나리오 | 성공 조건 |
|---|---|
| ① 화면 데이터 → 목업 | 트래픽에서 ↑↓로 요청을 고르고 주 동작 한 번 → 앱에서 다시 요청 → 상세가 최신 호출로 따라와 「목업」 배지를 보여요. 마우스 없이 가능. 응답을 고친 뒤에는 규칙 편집기의 「최근 요청」 줄이 고친 자리에서 확인해 줘요(가이드 따라 하기 실측: 전에는 조작 13번·창 넘나듦 2번·Resume 1번, 지금은 조작 9번과 눈길 한 번) |
| ② 에러 재현 | 규칙에서 「+ 응답」→ 상태 500 → 그 응답이 곧 앱이 받는 응답(표시됨) → 저장됨 |
| ③ 미완성 API | 빈 규칙 목록이 할 일을 알려주고 「+ 규칙」에서 경로·응답을 바로 써요. 새 규칙은 경로를 쓰기 전까지 아무것에도 응답하지 않아요 |
| ④ 차단·오프라인 | 「규칙 없는 요청」을 「차단」이나 오류로 바꾸면 헤더에서 그 상태가 보이고, 규칙을 끄면 허용 호스트로 가는 모든 요청이 실패해요 |
| ⑤ 첫 실행 | 허용 호스트가 없을 때 왜 아무것도 적용되지 않는지가 화면에 있고, 한 번에 추가 |
| ⑥ 「왜 안 먹지」 | 행에서 결과(목업/실서버/차단/확인 불가)가 보여요. 규칙이 맞는데 목업되지 않은 요청은 상세가 이유를 엔진 순서대로 한 줄로 말해요 — 앱 코드 차단(절대 목업 안 됨), Map Local 꺼짐 [켜기], 허용 호스트 아님 [허용 호스트에 추가], 규칙 꺼짐 [규칙 켜기], 또는 지금은 적용됨. 목업된 요청은 다른 규칙에 밀린 맞는 규칙을 이름으로 알려 줘요(그 규칙이 지금도 이길 때만). 꺼진 규칙만 맞고 가져올 응답이 없으면 그 이유를 고치는 버튼이 주 동작(⌘↩)이고, 같은 빈 규칙을 하나 더 만들지 않아요. 결과를 확인할 수 없는 요청에는 「지금은 적용됨」이라고 하지 않아요 |
| ⑦ 공유 | 「설정 복사/붙여넣기」의 뜻이 이름만으로 보이고, 결과를 알려줘요 |
| ⑧ 폭주 | 목록은 계속 흐르고 고른 것은 제자리에 있어요. 고른 뒤 쌓인 수가 현재 필터 기준으로 목록 위에 보이고, 「최신 보기」 한 번으로 따라잡아요. 스크롤할 만큼 길지 않은 목록에서는 새 요청마다 고른 행이 한 줄 내려가서 새 요청이 바로 보여요. 「일시정지」는 목록을 멈춰요. (전에는 고르면 시간순 보기가 멈췄는데, 처음 쓰는 사람 테스트에서 앱에서 방금 보낸 요청이 가려지는 것을 찾았어요) |

## 시각 언어 (2026-10-04, 「Necto Network에 지지 않게」)

근거: 우리 패널은 이미 `@necto/bridge`의 theme.css·components.css를 가져와요(Panel/src/style.css:1-2). Necto Network 패널이 쓰는 컴포넌트가 그 안에 다 있는데 우리는 `necto-button/field/tab` 정도만 써요. **먼저 호스트 컴포넌트를 쓰고, 그 위에 우리 도메인(목업·차단)만 더해요.**

- **쓸 Necto 컴포넌트**: `necto-table`(sticky 머리글, 26px 행, hover/선택 + 선택 행 왼쪽 accent 선), `necto-status-{ok,info,warning,danger,idle}`(색 점 + mono 숫자), `necto-segmented`(보기 전환), `necto-badge`, `necto-pairs`(상세 요약), `necto-tabs`(상세: 요약·요청·응답), `necto-empty`, `necto-notice`(배너), `necto-code-copy`(본문 복사), `necto-resize`(분할 폭), `necto-switch`, `necto-numeric`, `:focus-visible` 링.
- **두 축, 두 언어**: HTTP 상태는 Necto와 똑같이 색 점(2xx success · 3xx info · 4xx warning · 5xx·연결 실패 danger · 진행 중 idle). **결과**는 모양이 다른 알약 배지로 구분해요 — 상태 색과 섞이지 않게.
  - 목업 = `--ml-mock` 보라(옅은 채움 + 글자), 차단 = `--ml-block` 주황(옅은 채움 + 글자), 실서버 = 채움 없는 3차 텍스트(기본값은 조용하게), 확인 불가 = 점선 테두리 3차 텍스트.
  - 원칙: **기본은 조용하고 예외가 튀어요** — 목록을 훑을 때 목업·차단·오류만 눈에 들어와요(전주의 처리).
- **새 토큰은 Necto 팔레트와 같은 대비대**(실측 Necto: 라이트 5.6–6.5:1, 다크 6.1–7.8:1). 후보: `--ml-mock` 라이트 #7b3fd0(6.06) / 다크 #b691ff(6.89), `--ml-block` 라이트 ≈#a24a12 / 다크 #f0904a(7.14). 라이트·다크 모두 ≥4.5:1을 테스트로 고정.
- **덤**: 느린 응답(≥1s) 소요 시간을 warning 색, 메서드는 Necto처럼 단색(색은 결과·상태에만 써요 — 색의 뜻을 둘로 늘리지 않아요).
- **시작 시각은 현지화하지 않고 고정 형식**: Necto Network 패널처럼 로컬 시각 `HH:MM:SS.mmm`. 로캘 시계(「오후 12:46:21」)는 열보다 넓고 목록을 따라 비교하기 어려워요.
- **빈 목록은 `necto-empty`**: 트래픽 목록은 아무 요청도 오지 않았으면 「아직 요청이 없습니다」, 필터가 모두 가렸으면 「필터에 맞는 요청이 없습니다」와 [필터 지우기]를 보여줘요 — 가려졌을 뿐인 요청 위에 「요청 없음」을 띄우지 않아요(원칙 8).
- **라이트 모드도 실측**해요(Necto 설정의 테마 또는 `data-theme`).
