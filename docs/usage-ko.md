# Map Local 사용법

[English](usage.md)

패널에서 응답을 정하는 방법과, 앱이 그 응답으로 무엇을 하는지 설명해요. 패키지 설정은
[README](../README-ko.md)에, 배포 빌드에서 빼는 방법은
[release-builds-ko.md](release-builds-ko.md)에 있어요. 자주 하는 일의 짧은 단계는
[recipes-ko.md](recipes-ko.md)부터 보세요.

## 규칙이 적용되는 방식

앱 코드는 두 줄이에요. 플러그인을 등록하고 Necto를 시작해요. 허용 호스트·규칙·응답·지연·
오류는 모두 패널에서 정해요. 바꾸는 즉시 저장되고 다음 요청부터 적용돼요.

마지막 설정은 앱에 저장돼요. **Map Local이 켜져 있으면 Necto가 있든 없든 규칙이
적용돼요.** 다시 켠 앱의 첫 요청부터, Necto를 닫아 둔 동안에도 그래요. 무언가 적용되는
동안 앱에 [배지](#배지)가 보여요. 배지를 누르면 Map Local을 끌 수 있어요.

어떤 규칙도 답하지 않는 요청은 실제 서버로 가요. 허용 호스트가 비어 있으면 아무것도
목업하지 않아요.

### 한 번만 등록하기

Necto는 같은 ID(`io.github.ryan-son.maplocal`)의 두 번째 플러그인을 모든 빌드에서 거부하고,
debug에서는 assert로 멈춰요. 실행 중에 바꾸려면 먼저
`NectoSDK.unregister(id: "io.github.ryan-son.maplocal")`를 부르세요.

플러그인을 다시 만드는 것은 해가 없지만 바뀌는 것도 없어요. 엔진과 설정, 차단 호스트는
프로세스에서 한 번만 준비돼요. 나중에 만든 `NectoMapLocalPlugin(blockedHosts:)`는 처음 것의
차단 호스트를 그대로 써요.

## 규칙 매칭

다음이 모두 맞아야 규칙이 응답해요.

- **메서드.**
- **호스트.** 비우면 허용 호스트 전체예요.
- **경로.** `{id}` 같은 조각은 비지 않은 아무 조각과 맞아요. 경로는 앱이 보내는 대로
  퍼센트 인코딩해서 적어요. 공백 대신 `%20`이에요.
- **쿼리 조건.** 아래를 보세요.

### 쿼리 조건

쿼리 조건은 편집기의 「쿼리 조건」에 적는 키=값 줄이에요. 적은 키가 모두 정확히 그 값으로 있을
때 맞아요. 적지 않은 키는 보지 않아요. 값은 퍼센트 인코딩을 푼 글과 비교하고, `+`는 그대로
둬요. 조건이 없으면 「모든 쿼리」예요.

규칙 목록은 조건을 `GET /api/sites ?page=2`처럼 보여 줘요. 그래서 같은 경로의 규칙을 쉽게
구분할 수 있어요.

트래픽에서 만든 규칙에는 쿼리 조건이 없어요. 「이 쿼리일 때만」을 켜면 그 요청의 쿼리를
조건으로 옮겨요. 이미 맞는 규칙이 있으면 그 규칙에 응답을 더하므로 이 칸이 없어요.

### 여러 규칙이 맞을 때

쿼리 조건이 더 많은 규칙이 응답해요. 같으면 목록에서 위에 있는 규칙이 응답해요.
켜진 규칙이 켜진 다른 규칙과 같은 요청에 맞을 수 있으면, 편집기의 쿼리 조건 아래에 그 요청에
어느 규칙이 응답하는지 나와요. 둘보다 앞서는 세 번째 규칙이 있으면 그 규칙을 알려 줘요.

## 트래픽 탭

패널은 「규칙」과 「트래픽」 두 탭이에요. Necto의 언어 설정(한국어·영어)을 따라요.

트래픽 탭은 앱의 요청을 엔드포인트별(「엔드포인트」) 또는 시간순(「시간순」)으로 보여 주고,
요청마다 결과를 표시해요. 상태, 결과(「목업」·「실서버」·「차단」·「확인 불가」),
「허용 호스트만」으로 거를 수 있어요. 검색칸은 메서드·호스트·경로와 앱이 보낸 쿼리
문자열까지 찾아요(`page=2`, `siteId=101`).

시간순 보기에서 고른 요청은 새 요청이 위에 쌓여도 제자리에 있어요. 목록 위 줄이 쌓인 수를
세고, 「최신 보기」가 가장 최근 요청으로 옮겨 줘요. 목록을 멈추려면 「일시정지」를 눌러요.

요청을 고르면 응답이 보이고, 거기서 규칙을 만들어요.

1. 「이 응답으로 목업」을 눌러요. 응답을 볼 수 없으면 버튼이 「빈 응답으로 목업」이에요.
   목업하면 그 요청의 호스트도 허용 호스트에 들어가요. 버튼 아래 줄이 그렇게 알려 줘요.
2. 「규칙」 탭에서 응답을 고쳐요.

아직 아무것도 목업하지 않고 호스트만 허용하려면, 패널 머리의 「+ 호스트」 칸에 호스트나
URL을 입력하거나 붙여 넣고 Return을 눌러요.

맞는 규칙이 있는데 목업되지 않은 요청이면, 상세가 그 이유를 한 줄로 알려 줘요. 모든 쿼리에
응답하는 규칙이 목업한 요청이면 「규칙 열기」 옆의 「이 쿼리 전용 규칙」이 그 요청의 쿼리를 조건으로
한 규칙을 만들어요. 새 규칙은 앱이 지금 받는 응답으로 시작해요. 트래픽에서 쿼리 조건과 함께
만든 규칙은 처음 응답할 때까지 지켜봐요. 그 사이에 경로는 맞는데 쿼리 때문에 응답하지 못한
요청이 오면, 어느 조건 때문인지와 해결 버튼을 보여 줘요.

### 실제 응답 캡처하기

실제 응답(상태·헤더·본문)을 보고 새 규칙에 채우려면 Necto 네트워크 플러그인을 Map Local
**다음에** 등록하세요.

```swift
#if DEBUG
import NectoURLSessionCapture   // URLSessionNetworkPlugin은 이 모듈에 있어요
#endif

#if DEBUG
NectoSDK.register(NectoMapLocalPlugin())      // 먼저
NectoSDK.register(URLSessionNetworkPlugin())  // 나중에
NectoSDK.start()
#endif
```

순서가 중요해요(실측).

- Map Local을 먼저 등록하면 목업된 요청이 목업 응답과 함께 트래픽 탭에 보여요. 요청마다 한
  번씩만 기록돼요.
- 네트워크 플러그인을 먼저 등록하면 목업된 요청이 트래픽 탭에서 사라지고, 실서버로 간 요청이
  두 번 기록돼요. 패널이 이를 감지하면 경고를 띄워요.
- 네트워크 플러그인이 없어도 탭은 요청을 보여 주지만 응답은 볼 수 없어요. 요청으로 규칙을
  만들면 빈 200 JSON 응답이 돼요.

대가가 있어요. Necto 관찰자는 요청을 `URLSession(configuration: .ephemeral)`로 다시
보내요. 그래서 앱 세션의 delegate(인증 챌린지·피닝), 공용 쿠키, URLCache를 우회해요.
캡처는 선택 기능이에요.

이 기능은 Necto 문서에 없는 동작에 기대요. 패널은 다른 플러그인의 브리지, 곧 Necto 네트워크
플러그인의 `necto.device.network-records.*`를 불러요. Necto 0.2.0은 이를 연결해 주지만,
브리지 문서는 앱 브리지를 한 플러그인 범위로 설명해요. 패널은 연결할 때마다 사용 가능 여부를
확인하고, 기록을 쓸 수 없으면 Necto가 준 이유를 보여 줘요. 규칙 탭은 기록 없이도 동작해요.
이후 Necto 릴리스에서 바뀔 수 있어요.

## 허용 호스트와 차단 호스트

- **허용 호스트가 없으면 아무것도 목업하지 않아요.** 「+ 호스트」 칸으로 호스트를 넣으세요.
  트래픽 탭에서 요청을 목업해도 그 호스트가 들어가요.
- **유니코드(IDN) 호스트는 punycode로 적어요.** 앱 요청의 유니코드 호스트는 엔진에 퍼센트
  인코딩된 채 오므로 `한국.kr`로 허용하면 어떤 요청과도 맞지 않아요. 「+ 호스트」 칸은 이런
  호스트를 더하지 않고 「유니코드 호스트는 punycode(xn--…)로 입력하세요」라고 알려요.
  예: `xn--3e0b707e.kr`.
- **운영 호스트는 앱 코드에서 차단해요.**
  `NectoMapLocalPlugin(blockedHosts: ["api.example.com"])`로 넣은 호스트는 절대 목업되지
  않아요. 스킴·포트·대소문자는 무시하고, 패널에서는 이 목록을 바꿀 수 없어요. **요청을
  막지는 않아요.** 목업되지 않은 채 실서버로 그대로 가요. 운영을 목업하지 않게 지킬 뿐,
  운영에 닿는 것을 막지는 않아요.
- **규칙 없는 요청을 차단하거나 실패하게 해요.** 패널의 「규칙 없는 요청」이 허용 호스트로
  가는 요청 중 규칙이 없는 것이 무엇을 받을지 정해요. 다른 호스트는 항상 실서버로 가요.
  - 「차단(421)」: 그 요청은 421을 받아요. 가짜 토큰이 목업 안 된 실서버 요청에 실려 401이나
    강제 로그아웃이 나는 것을 막아요. 인증을 목업할 때 권해요.
  - 「인터넷 연결 없음 (-1009)」, 「연결 끊김 (-1005)」, 「시간 초과 (-1001)」: 서버에 닿을 수
    없는 것처럼 그 `URLError`로 실패해요. 규칙은 여전히 응답하니, 함께 실패해야 하는 규칙은
    꺼 두세요. 「시간 초과」여도 요청은 바로 실패해요. 늦게 실패하게 하려면 규칙 응답에 그
    오류와 지연을 함께 주세요. 기기 자체의 네트워크 상태(`NWPathMonitor`)는 바뀌지 않아요.

## 인증 규칙

로그인이나 토큰 요청에 답하는 규칙에는 「인증 규칙」(「로그인·토큰을 내주는 응답입니다」)을
켜 두세요. 그 규칙이 응답하면 앱 배지에 `Map Local 🔑`가 뜨고, 패널에 「로그아웃했습니다」
확인이 나타나요. 규칙을 끄거나 지울 때는 앱에서 먼저 로그아웃하라고 안내해요.

## 배지

무언가 적용되는 동안 앱에 작은 `Map Local` 배지가 보여요.

- 켜진 규칙이 허용 호스트에 응답할 때
- 규칙 없는 요청을 차단하거나 실패하게 할 때
- 목업 세션이 남아 있을 수 있을 때

적용되는 것이 없으면 앱은 아무것도 보여 주지 않아요.

배지는 화면 아래 홈 인디케이터 오른쪽 옆에 있어요. 홈 버튼이 있는 기기에서는 상태 막대에
있어요. 배지 자리만 터치를 받고, 나머지 터치는 모두 앱으로 가요. 키보드가 올라온 동안에는
숨어요. VoiceOver는 버튼으로 읽어요.

### 앱에서 끄기

배지를 누르면 적용 중인 것이 나와요. 규칙 최대 3개를 패널과 같은 이름으로, 그리고 차단
여부를 보여 줘요. 「Map Local 끄기」는 패널의 스위치와 같은 설정을 쓰므로 패널도 따라
바뀌어요. 목업 세션이 실서버로 갈 수 있으면 먼저 로그아웃하라고 안내해요.

시트는 기기 언어를 따라요. 기기가 한국어를 우선하면 한국어, 아니면 영어로 보여요.

## 되돌리기와 키보드

규칙이나 응답을 지울 때 먼저 묻지 않아요. 대신 「되돌리기」를 보여 줘요.

Necto는 ⌘Z(편집 메뉴의 실행 취소)와 Esc를 직접 쓰므로, 이 키는 패널에 오지 않아요. 그래서
되돌리기·닫기·지우기에는 늘 보이는 버튼(「되돌리기」, ×, ⓧ)이 있어요.

패널에서 쓰는 키예요. ↑↓, Return, ⌘↩, `/`는 Necto 0.2.0에서 실측했어요.

| 키 | 동작 |
| --- | --- |
| ↑ ↓ | 목록에서 이동 |
| Return | 상세의 주 동작으로 포커스 이동 |
| ⌘↩ | 「이 응답으로 목업」(버튼에 단축키가 보여요) |
| `/` | 검색 |
| ← → | 분할 손잡이에서 목록 폭 조절(두 번 누르면 기본 폭) |

## 패널이 볼 수 있는 것

- **패키지를 링크하는 것이 곧 권한이에요.** Necto는 디바이스 플러그인에 설치 확인 창을 띄우지
  않아요. 앱에 패키지를 넣으면 그 패널이 플러그인의 디바이스 브리지 전체에 접근해요
  ([Necto: bridges](https://github.com/toss/necto/blob/main/docs/bridges.md)). 설정을 읽고
  바꾸고, 토큰을 포함한 모든 요청 기록을 봐요. 직접 관리하는 빌드에만 넣으세요.
- **내보내기와 캡처는 값을 그대로 둬요.** 「설정 복사」, 트래픽 캡처, 요청 기록은 토큰·쿠키·
  비밀번호를 가리지 않고 원래 값 그대로 실어요. Necto 네트워크 기록과 같아요.
- **복사할 때 경고하지만 값은 바꾸지 않아요.** 복사한 설정에 다음 중 하나가 있으면 패널이 한
  줄로 경고해요. JWT 모양 값, `auth` 태그가 붙은 규칙, Authorization·Cookie·Set-Cookie 헤더
  값, 또는 이름이 token·secret·password·api key·session인 응답 헤더·쿼리 조건 키·본문 JSON 키의
  값이에요. 공유하거나 커밋하기 전에 확인하세요.

## 알려진 한계

iOS 26.4 시뮬레이터와 Necto 0.2.0에서 실측했어요.

- **`NectoSDK.register`보다 먼저 얻은 세션과 설정은 가로채지 않아요.** 등록하면 Map Local이
  `URLSession.shared`와, 그 뒤에 읽는 모든 `URLSessionConfiguration.default`·`.ephemeral`의
  맨 앞에 들어가요. 그 전에 읽은 설정은 예전 목록을 그대로 갖고, 그 설정으로 만든 세션도
  마찬가지예요. `URLSession.shared`는 먼저 썼어도 가로채요. 등록은 `App.init`이나
  `application(_:willFinishLaunchingWithOptions:)`처럼 앱 시작의 가장 이른 시점에 두세요.
- **`protocolClasses`를 통째로 바꾼 설정에서는 Map Local이 빠져요.** 일부 SDK처럼
  `config.protocolClasses = [MyProtocol.self]`로 쓰면 Map Local이 들어 있던 목록이 사라져요.
  기존 목록 앞이나 뒤에 붙이는 것은 괜찮아요. 되살리려면 목록을 정한 뒤 맨 앞에 `NectoMapLocalPlugin.protocolClass`를 넣으세요.

  ```swift
  #if DEBUG
  config.protocolClasses = [NectoMapLocalPlugin.protocolClass] + (config.protocolClasses ?? [])
  #endif
  ```

  `protocolClass`를 넣은 설정은 언제 만들었든, 플러그인을 등록하기 전이어도 가로채요. 그래서
  일찍 있어야 하는 세션도 이렇게 해결돼요.
- **`URLSession` 위에 만든 라이브러리(예: Alamofire, Moya)도 같은 조건에서 동작해요.** 그
  라이브러리의 세션을 만들기 전에 Map Local을 등록해야 하고, `protocolClasses`를 바꾼 설정에는
  `NectoMapLocalPlugin.protocolClass`를 맨 앞에 넣어야 해요. Alamofire `AF` 같은 공유 세션은
  무언가가 처음 쓸 때 만들어지므로, 등록 전에 누군가 닿으면 등록 전에 만든 세션이 돼요.
- **백그라운드 세션은 가로채지 않아요.** `URLSessionConfiguration.background(withIdentifier:)`의
  전송은 앱 밖의 시스템 프로세스에서 돌고, 그 프로세스는 앱의 `URLProtocol`을 보지 않아요.
  Debug 빌드에서는 포그라운드 세션을 쓰거나, 전송을 목 서버로 보내세요.
- **`WKWebView`는 가로채지 않아요.** 페이지 로드, `fetch`, `XMLHttpRequest` 모두요. WebKit은
  별도 프로세스에서 직접 통신해요.
- **목업 3xx는 따라가지 않고 그대로 돌려줘요.** 앱은 `Location` 헤더가 붙은 3xx를 받고, 그
  목적지는 요청되지 않아요. **실제** 리다이렉트의 목적지가 규칙과 맞으면 그 홉은 목업돼요.
  첫 요청은 서버가, 리다이렉트된 요청은 규칙이 답해요.
- 목업 응답의 `Set-Cookie`는 세션의 쿠키 저장소가 아니라 **항상 `HTTPCookieStorage.shared`**에
  들어가요. 세션 저장소에 닿는 공개 API가 없어요. ephemeral 세션이나 별도 쿠키 저장소를 쓰는
  세션이라면 목업 쿠키가 그 세션에 반영되지 않고 공용 저장소에 남아요. Map Local을 끈 뒤에도
  공용 저장소를 쓰는 세션의 실제 요청에 실릴 수 있어요.
- 서버 계약 변경을 가릴 수 있어요. 계약 검사는 다른 도구의 몫이에요.

## 문제 해결

| 증상 | 확인 |
| --- | --- |
| 규칙이 맞지 않아요 | 허용 호스트에 그 호스트가 있나요? 차단 호스트는 아닌가요? 트래픽 탭의 결과가 「실서버」인가요? 행의 호스트가 흐리면 허용 호스트가 아니에요 |
| 패널에 「앱 연결을 기다리는 중…」이 보여요 | 앱이 Debug로 실행 중인가요? Necto에서 그 앱을 골랐나요? |
| `module<NectoMapLocalPlugin>` 컴파일 오류 | [구성 이름 규칙](release-builds-ko.md)을 보세요 |
| 허용 호스트로 가는 모든 요청이 421을 받아요 | 「규칙 없는 요청」이 「차단」이에요. 필요한 규칙을 더하거나 「실서버로 보내기」로 바꾸세요 |
| 허용 호스트로 가는 모든 요청이 오프라인처럼 실패해요(-1009, -1005, -1001) | 「규칙 없는 요청」이 오류로 되어 있어요. 필요한 규칙을 더하거나 「실서버로 보내기」로 바꾸세요 |
| 맞는 규칙이 있는데 목업되지 않았다고 트래픽 상세가 알려요 | 한 줄 이유를 따르세요. Map Local 꺼짐, 허용 호스트 아님, 규칙 꺼짐, 앱 코드에서 차단한 호스트(절대 목업 안 됨) 중 하나예요 |
| Necto에 앱이 보이지 않아요 | 한 앱의 빌드 여러 개(Dev와 운영 등)가 나란히 깔려 있을 수 있어요. 플러그인을 등록하는 코드가 든 빌드를 실행하세요 |
| 새로 설치한 앱의 요청이 운영으로 가요 | 앱에서 서버 환경을 바꾸기 전까지는 앱의 기본값이 운영일 수 있어요. `blockedHosts`는 운영을 목업하지 않게 할 뿐, 그 요청은 통과시켜요 |
